## 1. 프로젝트 개요

### 배경
교민 님은 단타·스윙·중장기를 모두 하는 트레이더로, **본인이 그린 추세 채널**을 최우선 지표로 삼아
채널 하단 매수 / 상단 분할매도를 한다. 이미 「포지션 장부 플레이북 v1」(피보나치 채널 + 이평선 정배열 추세스위치 + MACD/거래량 확인 + 지지선 이탈 손절)을 세워둔 상태.

### Pain Points
- TradingView는 차트·드로잉·알람은 잘하지만 **"얼마를 살지"(포지션 사이징)를 안 해준다** — 진입·손절은 정해도 수량은 감으로.
- 관심종목이 여러 개일 때 **지금 어느 종목이 매수존에 왔는지** 한눈에 안 보인다.
- 3장부(데이/포지션/중장기)와 매매 규칙 준수 여부를 **기록·집계할 곳이 없다.**
- 기울어진 추세 채널은 매일 값이 변해 **오늘의 하단/상단을 매번 계산**하기 번거롭다.

### 핵심 의사결정 (이 대시보드가 돕는 결정)
> **"지금 내 관심종목 중 매수존에 온 게 무엇이고, 내 리스크 규칙상 얼마를 사야 하는가?"**

### 목적 / 핵심 가치
차트 도구가 아니라 **TradingView 위에 얹는 "결정 + 규율 + 포지션 관리 콕핏"**.
TradingView가 못 하는 포지션 사이징·채널 사냥 리스트·매매 장부·리스크 규율을 담당.

### 대시보드 유형
**운영형(Operational)** — 장중 수시 확인, 즉각 행동 유도. KPI 5~10개, 5초 룰.

## 2. 데이터 소스

| 소스 | 형태 | 용도 | 비고 |
|------|------|------|------|
| `data/watchlist.json` | 로컬 JSON | 종목·장부·채널 앵커·현재가·체크리스트 | 사용자 입력 |
| `data/positions.json` | 로컬 JSON | 열린/청산 포지션, 실현 R | 앱 생성 |
| `data/settings.json` | 로컬 JSON | 계좌·리스크%·히트상한·근접임계 | 사용자 설정 |
| `data/events.json` | 로컬 JSON | TradingView 웹훅 알림 수신 로그 | 웹훅 입력 |
| TradingView 임베드 위젯 | 외부 | 지수 차트·시세 표시 | 무료, 읽기전용 |
| (선택) TradingView 알람 웹훅 | 외부 push | 채널 도달 알림 | Pro 플랜 필요 |

**결정적 제약**: TradingView에 손으로 그린 채널 좌표를 외부에서 읽는 공개 API 없음 →
채널은 **하단선 앵커 2점 + 폭**을 한 번 입력받아 앱이 선형 외삽으로 오늘값 계산.

## 3. 데이터 파이프라인

```
[사용자] 채널 앵커 2점 입력 ─┐
                            ├─► lib/channel.ts (선형 외삽) ─► 오늘 하단/상단 ─► 근접 판정(zone)
[사용자] 현재가 입력 ────────┘
[설정] 계좌·리스크% ─► lib/risk.ts ─► 매수수량·1R·R배수·포트폴리오 히트
[TradingView] 추세선 알람 ─► /api/tv-webhook (POST) ─► events.json ─► 폴링(15s) ─► 브라우저 알림+소리
```

핵심 수식:
- 하단 오늘값 `lower(today) = p2 + ((p2−p1)/(t2−t1)) × (today − t2)`, 상단 `= lower + width`
- 매수수량 `= 계좌 × 리스크% ÷ (진입 − 손절)`
- 실현/목표 R `= (청산 또는 목표 − 진입) ÷ (진입 − 손절)`
- 포트폴리오 히트 `= Σ (진입−손절)×수량 / 계좌`

## 4. 대시보드 화면 (View별 기능 정의)

### View 1 — 시세 콕핏
- **목적**: 국내·미국 주요 지수를 한 화면에서 상황 파악.
- 표시: 코스피·코스피200·나스닥종합·나스닥100선물·S&P500·S&P500선물 (TradingView 위젯 + 티커테이프).
- 우선순위: 낮음(맥락용). 데이터 투명성: 출처=TradingView, 갱신=실시간(위젯).

### View 2 — 채널 사냥 리스트 (핵심) ★
- **목적**: 지금 매수존/분할매도존에 온 종목을 즉시 식별.
- KPI/표시: 종목·장부 / 오늘 하단 / 현재가(입력) / 오늘 상단 / 하단까지% / 상단까지% / 상태 뱃지.
- 상태: 매수존 근접 · 중립 · 분할매도 근접 · 하단 이탈(손절 경보).
- 플레이북 게이트: 정배열·MACD·거래량·반등캔들 토글(규칙대로 들어가는지 확인).
- AI/인사이트: 근접% 임계 초과 시 색·뱃지로 경고 (View당 규칙 소수).
- 하단 알림 패널: TradingView 웹훅 수신 로그 + 브라우저 알림/소리 + 확인처리.

### View 3 — 포지션 사이징 계산기
- **목적**: 진입 전 "얼마 살지"를 규칙(1~2% 룰)으로 확정.
- 입력: 종목·장부·진입가·손절가(채널 하단)·목표가(채널 상단).
- 출력: 매수 수량 · 1R · 주당 리스크 · 총 매수금액 · 목표 R배수 · 포트폴리오 히트(반영 후) + 상한 초과 경고.
- 액션: "장부에 진입 기록" → View 4로.

### View 4 — 매매 장부
- **목적**: 규칙 준수·성과를 기록·집계.
- 표시: 열린 포지션(청산 입력) / 청산 기록(실현 R·손익) / 요약(승률·기대값 R·히트).
- 3장부 태그로 데이/포지션/중장기 구분(섞지 않음).

### 설정
- 계좌 규모 · 트레이드 리스크% · 포트폴리오 히트 상한% · 매수/분할매도 근접 임계%.

## 4.5 디자인 입력 자료

- 톤&무드: 트레이딩 터미널풍 **다크 테마** (배경 #0b0e14, 패널 #131722).
- 시맨틱 컬러: 매수/지지=초록(#22c55e), 매도/상단=호박(#f59e0b), 손절/위험=적색(#ef4444), 보조=회색.
- 숫자는 tabular-nums 정렬, ₩ 통화·% 포맷, YYYY-MM-DD 날짜.
- 디바이스 우선순위: 데스크톱(장중 모니터) > 태블릿.

## 5. 기술 스택

| 기술 | 용도 | 선택 이유 |
|------|------|----------|
| Next.js 14 (App Router) | 프레임워크 | 통관 대시보드와 동일 컨벤션, API 라우트 내장 |
| TypeScript | 타입 안전 | 금융 계산 로직 안정성 |
| Tailwind CSS | 스타일 | 빠른 다크 테마 |
| TradingView 임베드 위젯 | 차트/시세 | 무료·즉시, 드로잉은 앵커로 우회 |
| 로컬 JSON 사이드카 | 저장 | 단일 사용자·원본마스터 없음. L5에서 Supabase+KIS API 승격 |

순수 로직: `lib/channel.ts`(외삽·근접), `lib/risk.ts`(사이징·R·히트·기대값), `lib/notify.ts`(알림).

## 6. 비기능 요구사항

- **반응형**: 데스크톱 우선, 태블릿 지원(가로 스크롤 테이블).
- **갱신**: 시세 위젯=실시간, 알림 폴링=15초, 채널값=페이지 로드 시 오늘 기준 재계산.
- **성능**: 초기 로딩 3초 이내(로컬).
- **인증**: v1 없음(로컬 단일 사용자). 외부 노출(터널) 시 접근 제어는 로드맵.
- **알림**: 브라우저 Notification + WebAudio 비프. 웹훅 수신은 Pro+터널 필요.
