## 1. 관통하는 의사결정 원칙 (가장 중요 — 먼저 읽기)

이 결정들은 세션 중반에 확립됐고 이후 모든 작업의 전제다.

1. **원본 마스터 보호 = 사이드카 패턴.**
   - 이유: 교민이 손으로 만든 실제 마스터 엑셀이 단일 진실 소스이고 서식·수식이 있을 수 있음. SheetJS(커뮤니티)는 쓰기 시 서식을 잃음. 비개발자 단일 파일 워크플로우라 원본을 건드리면 위험.
   - 그래서: 앱은 마스터를 **읽기만** 하고, 검토/업로드/이름수정/삭제/신규등록은 전부 `.data/sidecar.json`에 기록 → `loadData()`에서 병합.
   - (배경: 처음엔 "마스터에 직접 쓰기"로 만들었다가, 실제 파일 발견 후 사용자 선택으로 사이드카로 전환함.)

2. **실데이터 구조에 앱을 맞춘다 (앱 양식을 강요하지 않음).**
   - 교민의 마스터는 원본 PRD 컬럼 구조(`공급사명`·`품목(SKU)`·`[A]~[G]` 그룹 컬럼). 앱의 정규 양식과 달라 못 읽고 있었음 → 어댑터(`lib/realMaster.ts`)로 그 구조를 그대로 매핑.

3. **검토 게이트 = 엄격 (검토해야 다음 단계).**
   - 사용자 선택: 서류는 "받음"만으로는 부족, **직접 검토(조건 확인)를 거쳐 검토완료**여야 완료로 침.
   - 단계: 미착수 → 진행중 → **발주 가능** → 통관 가능 (이상 있으면 검토 필요).

4. **발주 가능 = 성분표 + 제조업소코드(K-MFDS)만 검토완료되면.**
   - 사용자 의도: 모든 서류 다 받고 발주하면 늦음. 최소 필수(성분표·제조업소코드)만 확인되면 **우선 발주하고 나머지는 리드타임에 보완**.

5. **자동 분류 = 파일명 + PDF 텍스트 휴리스틱** (이미지는 파일명). AI 비전·정밀 판독은 v2.

6. **미국 = FTA 미적용** (PRD §3.5 기준 — 원산지증명서 필요). 국가에서 FTA 자동 도출.

## 2. 진행 흐름 (사용자 의도 → 결정 → 결과)

### ① 착수 — PRD + Claude Design → 구현
- **의도**: PRD와 Claude Design 프로토타입을 실제 앱으로.
- **결정(질문)**: 기술스택 → **Next.js**(로컬 폴더 저장이 핵심이라 서버 필요). 첫 빌드 → **UI 픽셀-퍼펙트 포팅 + 실제 폴더 저장**.
- **결과**: 3화면 포팅, 조건 분기 엔진(`requiredDocs`), 실제 폴더 저장(Node fs, §4 이름규칙), 현황 Excel 다운로드.

### ② 실제 엑셀 연동
- **의도("진행해줘")** → 방향 질문 → **실제 엑셀 연동** 선택.
- **결정**: 정규 스키마 정의(읽기/쓰기 공용, 라운드트립 보장) + 없으면 샘플 폴백 + **마스터 템플릿 다운로드** 버튼.
- **결과**: `lib/masterExcel.ts`, `lib/dataSource.ts`, 데이터 출처 뱃지.

### ③ 마스터 쓰기(write-back) → [이후 사이드카로 대체됨]
- **의도("응응")** → **마스터 엑셀 쓰기** 선택.
- 업로드 결과를 마스터에 기록(atomic write) 구현. **→ 실제 파일 발견 후 원칙 1(사이드카)로 전환되어 폐기됨.**

### ④ 신규 와이너리 등록 + 자동 분류 (메인 디테일 요청)
- **의도**: 메인에 "신규 와이너리 등록" 버튼 → 박스에 받은 파일 넣으면 **자동 분류 + 와이너리 자동 생성 + 카드 자동 표시**.
- **현실 반영(내가 짚음)**: 파일만으로 와이너리 이름·국가·FTA까지 자동 추출은 불안정 → **간단 폼 + 파일 드롭** 으로 합의. 분류는 **파일명 + PDF 텍스트** 선택.
- **결과**: `RegisterModal`, `lib/classify.ts`, `/api/register`.

### ⑤ 직접 검토 단계
- **의도**: 분류 후 각 서류가 조건에 맞는지 **꼼꼼히 직접 검토**하는 단계 필요.
- **결정**: **검토해야 다음 단계(엄격)**. §3 조건을 서류별 체크리스트로 제공.
- **결과**: `ReviewModal`(조건 체크 + 검토완료/이상), `CHECKLIST` 맵, viewmodels 검토 게이트로 대대적 재작성, 샘플에 검토완료 미리 채움.

### ⑥ 실제 마스터 발견 → 어댑터 + 사이드카 전환 (분기점)
- **사건**: 검토 API를 실서버로 테스트하다 교민의 **실제 마스터가 존재**함을 발견(공급사 8행, 실데이터). 앱이 스키마 불일치로 못 읽어 "샘플"로 표시 중이었음. 그리고 **내 테스트가 원본에 `검토` 행 1개를 남기는 실수**(서식 손실 가능) 발생.
- **결정(사용자)**: 앱을 **실제 파일 구조에 맞춰 읽기** + **원본 보호 + 사이드카 기록**.
- **결과**: `lib/realMaster.ts`(원본 구조 매핑·국가 정규화·FTA 도출·"필수아님"→naDocs·"있음"→수령), `lib/sidecar.ts`, `dataSource` 전면 개편(스키마 자동 감지 + 사이드카 병합). 실데이터 5곳 표시 확인.

### ⑦ 상세 화면 간소화 + 와이너리 편집
- **의도**: 상세 업로드의 서류종류 드롭다운 제거 → **박스에 넣으면 자동 분류·저장**. 그리고 **와이너리 이름 수정·삭제**.
- **결과**: 상세 드롭존 다중파일 자동분류(`/api/upload` docId 없으면 분류), 이름수정(사이드카 override), 삭제(사이드카 hidden — 숨김). `/api/winery`.

### ⑧ 일괄 자동 검토
- **의도**: 서류를 넣으면 **버튼 하나로 일괄 자동 검토**, 각 조건에 맞춰 판정. + 직접 실행해 확인.
- **결과**: `lib/autoReview.ts`, `/api/auto-review`, 상세에 `⚡ 일괄 자동 검토` 버튼. 실행 검증: CODORNIU 10건 전부 검토완료 → 통관 가능 이동 확인.
- **정직한 한계**: 마스터 칸이 "있음" 같은 상태 마커면 실제 파일이 없어 내용 검증 불가 → "알려진 이상 없음" 통과. 실제 검증은 **앱에 파일 업로드 시** PDF 내용(EEC·0%·SO2·주소대조)으로 수행.

## 3. 아키텍처 / 핵심 파일

```
dashboard-app/
  app/
    page.tsx                 # 서버 컴포넌트: loadData()로 데이터 주입
    api/upload/route.ts      # 파일 저장 + (docId 없으면) 자동 분류
    api/register/route.ts    # 신규 와이너리 등록 (폼+파일 분류)
    api/review/route.ts      # 단건 직접 검토
    api/auto-review/route.ts # 일괄 자동 검토
    api/winery/route.ts      # 이름수정 / 삭제
    api/export/route.ts      # 현황 xlsx 다운로드
    api/master-template/route.ts
  components/  DashboardApp(client 루트·state) · DashboardView · DetailView · SkuView
               · RegisterModal · ReviewModal · EmailModal · Sidebar · HoverButton
  lib/
    domain.ts       # 엔진(requiredDocs)·DOC_META·CHECKLIST·색상·타입·샘플 WINERIES/SKUS
    viewmodels.ts   # cardVM/detailData/dashData/insights/emailVM + 검토 게이트 상태 로직
    masterExcel.ts  # 앱 정규 스키마(템플릿/내보내기용) 읽기·쓰기
    realMaster.ts   # ★교민 실제 마스터 구조 어댑터(읽기 전용)
    dataSource.ts   # loadData(스키마 감지+사이드카 병합) / persist*(전부 사이드카)
    sidecar.ts      # .data/sidecar.json (reviews·uploads·wineries·overrides·hidden)
    classify.ts     # 파일명+PDF텍스트 자동 분류
    autoReview.ts   # 일괄 자동 검토 판정
```

**상태 흐름**: 서버 `loadData()`(마스터 읽기 → 어댑터/정규 파서 → 사이드카 병합) → `DashboardApp`(client, uploads/reviews 오버레이로 즉시 반영) → API 호출 시 사이드카 영구화 → `router.refresh()`로 재반영.

## 4. 현재 상태 / 데이터 사실

- 실제 마스터: 와이너리 시트 8행 중 **공급사명 있는 5곳만** 표시(CODORNIU SA·Azienda Uggiano·Domaine de la Combe·FRAV-ADVINI·HARLAN ESTATE). 나머지 3행은 공급사명 빈 메모성("캔와인"·"CLTS"·"Combe 홀딩") → 자동 제외.
- 검토 게이트 적용으로, 앱 내 검토 기록이 없으면 실데이터는 "진행중/검토 대기"에서 시작 → 검토/자동검토하면 발주가능·통관가능으로 이동.
- 거래유형·카테고리: 원본에 컬럼 없어 **기본값(신규 와이너리·스틸)**. FTA는 국가에서 도출.

## 5. 다음 작업 시 주의 / 남은 일

1. **테스트는 반드시 임시 경로로 격리**: 쓰기 API(upload/review/...)를 실서버로 테스트하면 실제 `DEST_ROOT`(OneDrive\신규통관서류)와 사이드카에 씀. 검증 시 `DEST_ROOT`/`MASTER_XLSX` 환경변수로 temp 인스턴스 사용. (이번에 실수로 원본 마스터 건드림 → 교민이 OneDrive 버전 기록 복원 또는 `검토` 시트 수동 삭제 필요)
2. **거래유형·카테고리 실제 값** 반영 방법(원본 컬럼 추가 / SKU 비고에서 도출 / 등록 시 입력).
3. **수동 재지정 UI**: 자동 분류 오판 시 종류를 직접 바꾸는 기능(현재 없음 — 드롭다운 제거 결정에 따름).
4. **삭제 복원(휴지통)** 여부 — 현재 hidden 으로 숨김만.
5. **v2 내용 검증 정밀화**: 성분합 100%·SO2·인증수출자번호 등 — 실제 파일 업로드 기반.
6. 보안: `next@14.2.5` 권고로 `^14.2.35`로 올림. `pdf-parse`는 inner lib 경로 import + `serverComponentsExternalPackages` 처리.
