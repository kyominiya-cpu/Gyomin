E-1. Skills란 무엇인가
핵심 정의
Skills는 반복 업무를 SOP(표준 운영 절차)로 정의하여 한 줄로 실행하는 기능이다. 
코드 없이 순수 지시서만으로도 만들 수 있고, 필요하다면 파이썬 스크립트를 포함할 수도 있다.
신입 사원 교육과 같은 원리
아침에 출근한 신입 사원에게 "이 순서대로 해"라고 체계화해서 알려주면 그대로 따르는 것과 같다. 
순서, 판단 기준, 예외 처리까지 정의해놓으면 AI도 그대로 실행한다.
원스텝 자동화
메일 수집 → 내용 정리 → 분석 → 보고서 작성 → 메일 발송. 
이렇게 여러 단계로 이루어진 업무를 스킬 하나로 묶으면, 단 한 줄의 명령으로 전체가 실행된다.
시연 사례: 트랜스크립트 정리 스킬
녹음 파일의 텍스트를 던지면 강의/미팅/인터뷰 유형을 자동 분석하여 구조화된 문서로 정리하는 스킬이다.

E-2. MCP vs Skills
MCP란
MCP(Model Context Protocol)는 외부 도구를 AI에 연결하는 표준 방식이다. 설치만 하면 다양한 외부 서비스에 바로 접근할 수 있다.

MCP 하나만 설치하면 연결


연결 작업이 어렵고 복잡
	
설치 후 바로 접근 가능
Context Window 문제 (예전 이야기)
2026년 1월 이전까지 MCP는 강력하지만 비용이 있었다. 설치한 MCP는 도구 설명이 항상 Context Window를 점유했다. 도구 50개짜리 MCP 하나 붙이면 설명만으로 약 77,000 토큰이 채워졌다 — 전체 기억 공간의 1/5에서 1/3. 작업할 공간이 그만큼 줄었다.
이 문제 때문에 Skills 방식이 더 효율적이었다. Skills는 디스크립션(짧은 설명문)만 상시 메모리에 올려두고, 실제 실행 로직은 호출 시점에만 로드한다.

E-3. Source of Truth - 스킬 만들기의 핵심 원칙
공식 문서가 기준이다
AI에게 "스킬 만들어줘"라고만 하면 AI가 자체적으로 형식을 만든다. 이 형식이 Claude Code의 실제 사양과 맞지 않으면 제대로 동작하지 않는다.
Source of Truth는 "내가 믿는 공식 소스를 기준으로 삼겠다"는 원칙이다. 공식 문서를 먼저 확보하고, 그것을 참조하여 스킬을 만들어야 한다.

추천 워크플로우

E-7. 스킬 만들기의 마인드셋
집요함이 핵심이다
스킬은 절대 한 번에 완성되지 않는다. AI가 대충 만들어주는 것은 쉽다. 진짜 핵심은 그 다음이다. 내 마음에 들 때까지 수정하고, 테스트하고, 다시 수정하는 과정에서 완성도가 올라간다.
점진적 개선 과정
대충 만들기 → 기본 동작 확인 → "이게 되네"
→ 구체적 수정 요청 → 테스트 → 다시 수정
→ 반복 → 완성도 높은 스킬 완성
​
첫 번째 목표는 일단 만들어서 "이게 되는구나"를 경험하는 것이다. 그 다음부터가 실전이다.
의도가 먼저다
스킬 제작에서 가장 중요한 역량은 기술이 아니라 "내가 무엇을 원하는지 명확하게 표현하는 것"이다. 과거에는 직접 찾아보고 배워서 실행하는 능력이 중요했다면, 지금은 명확한 의도를 문장으로 표현할 수 있으면 결과물이 나오는 시대다.
Plan Mode 권장
막막할 때는 Plan Mode를 먼저 켜고 시작한다. AI가 계획을 먼저 제시하고 확인을 받은 후 실행하기 때문에, 한 번에 완성도 높은 스킬을 만들 수 있다. Thinking Partner와 대화하며 업무를 정리한 뒤 Plan Mode로 전환하면 더 좋은 결과가 나온다. shift+tab
E-8. 작업을 잘게 쪼개라
AI에게 큰 덩어리 업무를 시키면 결과가 들쑥날쑥하다. 명확한 인풋과 아웃풋이 정의된 단위 작업에서 AI는 가장 정확하게 동작한다.
실천 방법:
최종 결과물을 먼저 정의한다
그 결과물을 만들기 위한 단계를 나열한다
각 단계를 하나씩 AI에게 요청한다
각 단계의 결과를 확인한 후 다음 단계로 넘어간다
스킬 설계에도 같은 원칙이 적용된다. SOP의 각 단계가 명확할수록 스킬의 품질이 올라간다.
