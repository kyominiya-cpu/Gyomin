Part 1: 폴더 구조 - 작업 공간 해부
여러분이 지금까지 써온 Claude Code, 그 안에 뭐가 있는지 해부해봅시다.
1-1. 직접 열어서 보기
Finder(탐색기)에서 같이 열어봅시다.
Mac: Finder에서 Cmd + Shift + . (숨김 파일 표시) > 홈 폴더 > .claude/
Windows: 탐색기 > 보기 > 표시 > 숨긴 항목 체크 > 사용자 폴더 > .claude\
​
1-2. 본사 vs 지점 비유
~/.claude/                        <-- "본사" (전체에 적용)
  |
  +-- CLAUDE.md                   <-- 나를 정의하는 문서
  |                                   "나는 누구이고, 어떻게 일하는지"
  |                                   Claude Code를 켤 때마다 이걸 먼저 읽음
  |
  +-- settings.json               <-- 전역 설정
  |                                   모델 기본값, 권한 설정 등
  |
  +-- skills/                     <-- 반복 업무 자동화 모음
  |     +-- excel-to-csv/         <-- 엑셀 변환 (이전 회차에서 만든 것)
  |     |     +-- SKILL.md
  |     |     +-- scripts/
  |     +-- thinking-partner/     <-- 사고 파트너
  |     +-- transcript-organizer/ <-- 녹음 정리
  |     ...
  |
  +-- subagents/                  <-- 전문 팀원 모음
  |     +-- research-worker.md    <-- 리서치 전문
  |     +-- content-worker.md     <-- 콘텐츠 작성 전문
  |     ...
  |
  +-- commands/                   <-- 슬래시 커맨드 모음
  |     +-- thinking-partner.md   <-- /thinking-partner로 실행
  |     +-- daily-note.md         <-- /daily-note로 실행
  |     ...
  |
  +-- plans/                      <-- Plan Mode에서 만든 계획서들
​
이게 '본사'예요. 여러분이 어떤 폴더에서 Claude Code를 열든, 이 설정이 항상 적용됩니다.
프로젝트별 구조 (지점):
내프로젝트/.claude/               <-- "지점" (이 프로젝트에만 적용)
  +-- CLAUDE.md                   <-- 이 프로젝트만의 규칙
  +-- settings.json               <-- 이 프로젝트만의 설정
​
본사 CLAUDE.md = '나는 우리 팀이고...' / 지점 CLAUDE.md = '이 프로젝트는 3월 캠페인이고...'. Claude는 두 파일을 다 읽고 합쳐서 이해합니다.
1-3. 핵심 포인트
CLAUDE.md  = Claude에게 "나는 이런 사람이야"라고 알려주는 문서
Skills     = 반복 업무를 패키지로 묶어놓은 것. SOP가 여기에 들어감
Subagents  = 특정 분야 전문 팀원. 별도 컨텍스트로 작업하고 결과만 가져옴
Commands   = 스킬을 빠르게 부르는 단축키
Plans      = Plan Mode에서 만든 계획서들

이 네다섯 가지가 합쳐져서 "나만의 AI 워크스페이스"가 됨
​
1-4. 실습 - 내 자산 확인
직접 확인해봅시다. Finder(탐색기)에서 ~/.claude/skills/ 폴더를 열어보세요.
여러분이 지금까지 만든 스킬들이 여기 다 있어요. 이게 여러분의 자산입니다. 
이 폴더가 쌓일수록 Claude Code가 여러분 업무에 최적화되는 거예요.
Part 2: CLAUDE.md 깊이 이해 + 실습
CLAUDE.md는 Claude가 가장 먼저 읽는 파일이에요. 여러분의 첫인상입니다.
2-1. CLAUDE.md가 하는 일
Claude Code를 시작할 때 가장 먼저 읽는 파일
= 여러분의 맥락, 규칙, 선호를 담고 있음
= 이 파일이 없으면 Claude는 여러분이 누군지 모름 -> 매번 설명해야 함
= 이 파일이 있으면 Claude는 "아, 이분은 이런 분이구나" -> 바로 맞춤 대화
​
2-2. 잘 쓴 vs 안 쓴 차이
차이를 직접 보여드릴게요.
안 쓴 경우:
나: "급여 계산해줘"
Claude: "어떤 회사인가요? 직원은 몇 명인가요? 어떤 기준으로?"
-> 매번 처음부터 설명해야 함
​
잘 쓴 경우:
나: "급여 계산해줘"
Claude: (이미 CLAUDE.md에 회사 정보, 직원 수, 급여 기준이 있으니)
-> 바로 작업 시작
​
이게 CLAUDE.md의 힘이에요. 한 번 잘 써놓으면 매번 같은 설명을 반복하지 않아도 됩니다.
2-3. 좋은 CLAUDE.md 4섹션 구조
# 나에 대해
- 이름, 역할, 소속
- 하는 일의 핵심

# 작업 스타일
- 선호하는 답변 방식 (간결하게? 자세하게?)
- 자주 하는 작업 유형
- 사용하는 도구/서비스

# 프로젝트별 맥락
- 현재 진행 중인 프로젝트
- 관련 파일 위치
- 팀 구성원 정보

# 규칙
- 반드시 지켜야 할 것들
- 하지 말아야 할 것들

​
2-4. 실전 팁
1. CLAUDE.md는 자주 업데이트하라 - 정적 문서가 아니라 살아있는 문서
2. Claude에게 "내 CLAUDE.md 업데이트해줘"라고 하면 대화 내용 기반으로 자동 갱신 가능
3. 너무 길면 오히려 혼란 -> 핵심만 간결하게
​
2-5. 실습: 각자 CLAUDE.md 업데이트
각자 CLAUDE.md를 열어서 업데이트해봅시다.
Claude Code에서:
"내 CLAUDE.md 보여줘"  -> 현재 내용 확인
"CLAUDE.md 업데이트해줘" -> 지금까지 대화 기반으로 갱신
​
CLAUDE.md는 한 번에 완성하는 게 아니에요. 새 프로젝트가 생길 때마다, 새로운 업무가 추가될 때마다 조금씩 갱신하는 겁니다.
Part 3: 권한 시스템 - 왜 매번 1번, 2번을 눌러야 했는가
3-1. 공감 도입
지금까지 Claude Code 쓰면서 가장 귀찮았던 게 뭐예요?
아마 대부분 '1번 눌러주세요', '2번 눌러주세요' 이거였을 거예요. 
파일 하나 읽을 때도, 명령어 하나 실행할 때도 매번 물어보잖아요.
3-2. 왜 그런지
기본적으로 안전 모드예요. 여러분의 파일을 함부로 건드리지 않겠다는 것. 
파일 읽을 때, 명령어 실행할 때, 파일 수정할 때 매번 물어보는 이유입니다.
3-3. settings.json permissions 구조
그래서 '이건 알아서 해' 하고 권한을 주는 거예요.
{
  "permissions": {
    "allow": [
      "Read",
      "Glob",
      "Grep",
      "WebSearch",
      "Bash(git status:*)",
      "Bash(git diff:*)",
      "Bash(git log:*)",
      "Bash(ls:*)",
      "Bash(python:*)"
    ]
  }
}

​
'Read'가 있으니까 파일 읽을 때 안 물어봐요. 'Bash(git status:*)'가 있으니까 git status 칠 때 안 물어봐요.
3-4. Bash 패턴 설명
패턴 구조: "Bash(명령어:인자)"

예시:
Bash(git:*)        -> git으로 시작하는 모든 명령어 허용
Bash(python:*)     -> python으로 시작하는 모든 명령어 허용
Bash(npm:*)        -> npm으로 시작하는 모든 명령어 허용
Bash(ls:*)         -> ls 명령어 허용

* 는 "뒤에 뭐가 오든 OK"라는 뜻
​
3-5. /permissions 슬래시 커맨드
settings.json을 직접 수정할 필요 없어요. 더 쉬운 방법이 있습니다.
/permissions
​
이렇게 치면 현재 권한 목록을 보여주고, 추가/삭제할 수 있어요.
3-6. 실습: 자주 쓰는 명령어 3개 등록
여러분이 가장 자주 쓰는 명령어를 최소 3개 /permissions에 등록해봅시다.
자주 등록하면 좋은 것들:

- Read, Write, Glob, Grep  (파일 관련 - 매번 물어보면 귀찮은 것들)
- Bash(git:*)              (git 관련)
- Bash(python:*)           (Python 실행)
- Bash(ls:*)               (폴더 확인)
- WebSearch                (웹 검색)
​
이것만 해도 체감이 확 달라질 거예요. '1번 눌러주세요'가 절반 이상 줄어듭니다.
Part 4: Bypass 모드 - 위임의 기술
4-1. --dangerously-skip-permissions
이름부터 무섭죠. 'dangerously'. 일부러 이렇게 지었어요. '이거 키면 Claude가 뭐든지 알아서 합니다'라는 뜻이니까.
claude --dangerously-skip-permissions

​
일명 YOLO 모드. You Only Live Once.
4-2. 적합한 상황 vs 주의할 상황
적합한 상황:
- 이미 충분히 익숙해진 작업
- 빠르게 반복 작업을 돌려야 할 때
- 테스트/실험할 때 (되돌릴 수 있는 것들)

주의할 상황:
- 중요한 파일을 다루는 작업
- 처음 해보는 작업
- 외부 서비스와 연동되는 작업 (메일 발송, API 호출 등)
​
4-3. 공식 권고
Claude Code 팀에서도 이런 말을 합니다.
"YOLO 모드보다 /permissions를 추천합니다.
필요한 것만 허용하고, 나머지는 확인하는 게
장기적으로 더 안전하고 효율적입니다."


​
4-4. 3단계 성장
1단계: 기본 확인 모드 (지금까지 한 것)
       -> 매번 물어봄. 안전하지만 느림.

2단계: /permissions 설정 (오늘 배운 것)
       -> 자주 쓰는 건 허용, 나머지는 확인.
       -> 대부분의 사람에게 이 단계가 최적.

3단계: Bypass 모드 (필요할 때만)
       -> 전부 허용. 빠르지만 주의 필요.
       -> 충분히 익숙해진 후에 선택적으로 사용.
​
대부분의 경우 2단계면 충분합니다. 급할 때만 3단계.
Part 5: 컨텍스트 관리 - 왜 대화가 길어지면 이상해지는가
5-1. 도입
이전에 토큰 얘기 잠깐 했었죠? 오늘은 그걸 실전에서 어떻게 관리하는지 알려드릴게요.
5-2. 컨텍스트 윈도우
컨텍스트 윈도우는 Claude의 작업 기억이에요. 한 번에 기억할 수 있는 양이 정해져 있습니다.
- 대화 초반에 한 얘기 -> 대화가 길어지면 잊음
- 파일을 많이 읽으면 -> 컨텍스트가 빨리 참
- 결과: 느려지고, 엉뚱한 결과가 나옴
​
5-3. 관리 명령어들
/compact - 대화 압축
/compact

하는 일:
- 지금까지 대화 내용을 요약
- 요약본만 남기고 상세 내용은 정리
- 컨텍스트 공간이 확보됨

언제 쓰나:
- 대화가 길어져서 느려질 때
- "아까 말한 거 기억해?" 했는데 못 알아들을 때
- 다른 주제로 넘어가기 전에
​
/clear - 대화 초기화
/clear

하는 일:
- 대화 내용 전부 삭제
- 완전히 새로운 대화 시작
- 하지만 CLAUDE.md는 다시 읽음

언제 쓰나:
- 완전히 다른 작업을 시작할 때
- 대화가 꼬여서 처음부터 다시 하고 싶을 때
​
/context - 컨텍스트 사용량 확인
/context

하는 일:
- 현재 컨텍스트 사용량을 색상 그리드로 시각화
- 초록 = 여유, 노랑 = 주의, 빨강 = 거의 참
​
/cost - 토큰 사용량/비용 확인
/cost

하는 일:
- 현재 세션의 토큰 사용량 표시
- 비용 추정치 표시
​
5-4. 새 세션 = 새 사람
이건 중요한 개념이에요.
Claude Code를 껐다 켜면:
- 어제 대화 기억 못 해요
- 지난 세션에서 뭘 했는지 모릅니다
- 완전히 새 사람이에요

하지만 새 사람이 읽고 오는 것들이 있어요:
- CLAUDE.md       -> 내가 직접 써놓은 지시서
- Skills 폴더     -> 반복 업무 매뉴얼
- settings.json   -> 권한, 모델 등 설정
- Memory 폴더     -> Claude가 스스로 쌓은 기억
​
5-5. CLAUDE.md vs Memory
CLAUDE.md를 배웠죠. 비슷한 듯 다른 게 하나 더 있어요.
CLAUDE.md
- 여러분이 직접 쓰는 문서
- 내가 Claude에게 알려주는 것
- 바뀌면 내가 직접 수정

Memory
- Claude가 대화하면서 스스로 저장하는 기억
- Claude가 알아서 쌓고, 다음 세션에서 자동으로 읽어옴
​
/memory

하는 일:
- Claude의 자동 메모리 설정을 관리
- 어떤 것들을 기억하고 있는지 확인
- 잘못 기억한 것이 있으면 수정/삭제
​
새 세션이 '새 사람'이긴 한데, CLAUDE.md도 읽고 오고, Memory도 읽고 옵니다. 그래서 쓰면 쓸수록 여러분에게 맞춰져요.
5-6. 실전 팁
/compact 치는 타이밍:
- 대화가 체감상 느려졌을 때
- "아까 말한 거" 했는데 못 알아들을 때
- 하나의 작업이 끝나고 다음 작업으로 넘어갈 때

새 세션 여는 게 나은 때:
- 완전히 다른 주제의 작업을 할 때
- 대화가 너무 꼬여서 정리가 안 될 때
- 이전 맥락이 오히려 방해가 될 때

핵심 원칙:
하나의 세션 = 하나의 목적
목적이 바뀌면 새 세션을 여는 게 낫다
​
Part 6: 모델 선택
6-1. 3가지 모델
Claude Code 안에서 모델을 바꿀 수 있어요.
Opus
- 깊은 사고, 복잡한 분석, 미묘한 맥락 이해
- 느리고 비쌈
- "이 보고서의 전략적 방향이 맞는지 검토해줘"

Sonnet
- 범용적이고 빠름
- 대부분의 업무에 적합
- "이 엑셀 데이터 정리해줘", "스킬 만들어줘"
- 기본 모델

Haiku
- 단순 작업에 특화, 매우 빠르고 저렴
- "이 파일 이름 바꿔줘", "이 텍스트 번역해줘"


​
6-2. /model 명령어
/model

-> 대화 중에 모델을 전환할 수 있음

예시:
1. Sonnet으로 데이터 정리 작업 시작
2. 복잡한 분석이 필요한 부분에서 /model -> Opus로 전환
3. 분석 끝나면 /model -> Sonnet으로 복귀
​
6-3. 실전 적용
리서치/분석/전략    -> Opus  (깊이 생각해야 하는 일)
스킬 실행/파일 작업 -> Sonnet (대부분의 일)
단순 변환/번역     -> Haiku  (반복적이고 단순한 일)
​
6-4. Max 플랜의 의미
Max 플랜의 핵심은 '더 많은 Opus를 쓸 수 있다'입니다.
Pro 플랜 ($20):
- Sonnet 위주, Opus 제한적

Max 플랜 ($100):
- Opus를 훨씬 많이 쓸 수 있음
- 복잡한 작업을 많이 하는 사람에게 적합
​
Part 7: /config와 유용한 빌트인 커맨드
7-1. /config
Claude Code에는 설정을 한 곳에서 관리하는 인터페이스가 있어요.
/config
​
조정 가능한 것들: 기본 모델 설정, 테마 변경 등
7-2. 오늘 배운 것 정리 - 이미 쓰고 있는 커맨드
/permissions 권한 관리 (Part 4)
/model       모델 전환 (Part 7)
/mcp         MCP 서버 연결 상태 확인 (Part 8)
/compact     대화 압축 (Part 6)
/clear       대화 초기화 (Part 6)
/context     컨텍스트 사용량 확인 (Part 6)
/cost        토큰 비용 확인 (Part 6)
​
7-3. 실무에서 바로 쓸 수 있는 커맨드
하나씩 보면 '이거 왜 이제 알려줘요?' 할 겁니다.
/copy - 결과물 바로 복사
/copy

하는 일:
- Claude의 마지막 답변을 클립보드에 복사
- 코드 블록이 여러 개면 어떤 블록을 복사할지 선택 가능

언제 쓰나:
- Claude가 만들어준 텍스트를 다른 곳에 붙여넣을 때
- 코드나 스크립트 결과를 복사할 때
​
/export [파일명] - 대화 통째로 저장
/export
/export 오늘작업.txt

하는 일:
- 현재 대화 전체를 텍스트 파일로 내보내기

언제 쓰나:
- 오늘 한 작업 과정을 기록으로 남기고 싶을 때
- 동료에게 공유할 때
​
/skills - 내가 가진 스킬 목록
/skills

하는 일:
- 현재 사용 가능한 커스텀 스킬 목록을 보여줌

언제 쓰나:
- "내가 어떤 스킬 만들었더라?" 기억 안 날 때
- 새 세션 시작하고 어떤 스킬이 있는지 확인할 때
​
/skills 쳐보면 여러분의 자산 목록이에요.
/usage - 남은 사용량 확인
/usage

/cost와 차이:
- /cost  = "이 대화에서 얼마 썼나" (현재 세션 비용)
- /usage = "전체적으로 얼마나 남았나" (플랜 한도)
​
/resume - 이전 대화 이어하기
/resume
/resume 세션이름

하는 일: 이전에 했던 대화를 불러와서 이어서 작업

언제 쓰나:
- 어제 하던 작업을 오늘 이어서 할 때
​
/rename [이름] - 세션에 이름 붙이기
/rename 3월캠페인작업
/rename VOC분석

하는 일: 현재 세션에 알아보기 쉬운 이름을 붙임
​
/rename과 /resume은 세트예요. 이름 붙여놓으면 나중에 찾기 쉽습니다.
/agents - 서브에이전트 관리
/agents

하는 일: 현재 설정된 서브에이전트 목록을 보여줌
​
/skills는 스킬 목록, /agents는 서브에이전트 목록입니다.
7-4. /simplify
이건 최근에 추가된 건데, 꽤 강력합니다.
/simplify

하는 일:
- 최근에 변경된 파일들을 자동으로 찾아서
- 3개의 에이전트가 동시에 코드 품질을 검토
- 중복 코드, 비효율적인 부분, 개선점을 찾아줌
​
스킬을 만들고 나서 /simplify 치면 '이 부분은 이렇게 하면 더 간단해요' 하고 알려줍니다.
7-5. 전체 커맨드 치트시트
다 외울 필요 없어요. 이 표만 기억하세요. 까먹어도 /만 치면 목록이 나옵니다.
[설정/관리]
/config      설정 인터페이스
/permissions 권한 관리
/memory      자동 기억 관리
/theme       테마 변경
/doctor      설치 점검
/init        프로젝트 초기화

[대화 관리]
/compact     대화 압축
/clear       대화 초기화
/resume      이전 대화 재개
/rename      세션 이름 붙이기

[모니터링]
/context     컨텍스트 사용량
/cost        세션 비용
/usage       플랜 한도
/stats       사용 통계

[작업 도구]
/model       모델 전환
/mcp         MCP 상태
/skills      스킬 목록
/agents      서브에이전트 관리
/copy        결과 복사
/export      대화 저장
/simplify    코드 품질 검토
​
이런 것들이 있다는 걸 아는 것만으로 충분해요. 필요할 때 꺼내 쓰면 됩니다.
