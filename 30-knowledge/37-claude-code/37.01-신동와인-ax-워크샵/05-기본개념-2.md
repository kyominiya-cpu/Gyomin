Part 1: Git 연동
1-1. 왜 Git인가
"지난번에 'PC에만 저장되는 거 아니에요?' 라는 질문이 있었어요. 아닙니다."
핵심 메시지:
회사 PC에서 작업 -> git push -> GitHub에 올라감
집에서 git pull -> 그대로 이어서 작업
어느 기기에서든 동일한 워크스페이스
비유:
Google Drive 같은 건데, AI가 이해하는 방식으로 동기화
버전 관리가 되니까 "어제 버전으로 돌아가줘"가 가능
1-2. GitHub 레포 만들기
시연 -> 따라하기
Step 1: GitHub.com 접속 -> New Repository
Step 2: Repository name 입력 (예: workspace)
Step 3: Private 선택 -> Create
Step 4: 나오는 URL 복사
​
워크스페이스와 연결:
# 이미 워크스페이스가 있는 경우
cd 내-워크스페이스-폴더

​
트러블슈팅 대비:
인증 창이 뜨면 -> GitHub 로그인
Personal Access Token 필요한 경우 -> 가이드 제공
"안 돼요" -> 서포터가 즉시 지원

시연 -> 따라하기

git push -u origin main

1. Skills     = 내 업무 SOP를 코드화한 것

2-4. MCP란 + 왜 Skills를 더 쓰는가
MCP (Model Context Protocol) 정의:
외부 도구를 Claude Code에 직접 연결하는 프로토콜
Notion, Slack, GitHub 등의 서버를 띄워서 Claude가 직접 접근
설정 예시 (보여주기만):
{

    "notion": {
      "command": "npx",
      "args": ["-y", "@notionhq/notion-mcp-server"],
      "env": { "NOTION_TOKEN": "..." }
    }
  }
}

​
Context Window 개념
"여기서 중요한 개념이 하나 있어요. Context Window."
Context Window = Claude가 한 번에 기억할 수 있는 양
​
예전 MCP 방식 (~2026년 1월 이전)
[Claude의 기억 공간] = [MCP 도구 설명들 항상 차지] + [실제 작업 공간]
                       ^^^^^^^^^^^^^^^^^^^^^^^^
                       쓰든 안 쓰든 항상 올라가 있음
​
도구 50개짜리 MCP를 붙이면 도구 설명만으로 약 77,000 토큰이 채워졌다. 전체 기억 공간의 1/5에서 1/3을 차지. 작업할 공간이 그만큼 줄어든다.
그래서 Skills가 나왔다
[Claude의 기억 공간] = [필요할 때만 스킬 로드] + [넓은 작업 공간]
                       ^^^^^^^^^^^^^^^^^^^^^^
                       호출할 때만 올라옴
​
2026년 1월, MCP도 같은 방식으로 바뀌었다
Anthropic이 Claude Code 2.1.7에 MCP Tool Search를 기본 탑재. 현재 모든 사용자에게 자동 적용.
지금 MCP 방식:
[Claude의 기억 공간] = [도구 이름·짧은 설명만] + [실제 작업 공간]
                       ^^^^^^^^^^^^^^^^^^^^^^
                       호출할 때 schema 꺼내옴

그럼 이제 Skills는 필요 없나 — 아니다
MCP와 Skills 모두 lazy 방식이 됐지만, 담는 것이 다르다.
MCP    = 도구 호출 규약 (이 함수를 이렇게 부르세요)
Skills = 도구 + 사용 절차 + 예시 + 주의사항 묶음
​
메일 보내는 작업 예시
상황
	
무엇이 부족한가


MCP만 있을 때
	
Gmail API 도구는 있지만, "어떤 톤으로 쓸지", "첨부 빠뜨리지 마", "가격은 본문 말고 첨부로" 같은 운영 룰은 매번 사람이 챙겨야 함


Skills로 묶어두면
	
도구 + 회신 톤 + 체크리스트 + 과거 사례까지 한 묶음으로 필요할 때 꺼내짐
결론
MCP는 이제 가볍다. 필요하면 여러 개 붙여도 된다
하지만 반복되는 작업 패턴이 있다면 Skills로 묶는 것이 효율적
MCP = 도구 자체, Skills = 그 도구를 우리 일에 맞게 쓰는 방법
둘은 경쟁이 아니라 역할이 다른 도구
"MCP는 도구를 연결하는 규약, Skills는 일하는 방식을 패키징하는 방법. 둘 다 필요할 때만 꺼내쓰는 구조로 정리되어 있다고 보면 된다."

Context 관점에서의 문제:
MCP 서버가 많으면 도구 설명만으로 Context의 10% 이상 차지
Claude Code는 자동으로 Tool Search를 활성화하지만, 근본적으로 Context 효율이 떨어짐
Skills는 호출될 때만 로드되므로 Context를 아낄 수 있음
API 토큰이란
참가자들이 "토큰이 뭐예요?"라고 물으면:
API 토큰 = 외부 서비스의 열쇠

비유:
- 회사 출입증이 있어야 회사에 들어갈 수 있듯이
- API 토큰이 있어야 Notion, Confluence에 접근할 수 있음
- 토큰 = "이 사람이 접근해도 돼" 라는 허가증

주의:
- 비밀번호와 같으므로 남에게 공유하면 안 됨
- 환경변수로 관리 (코드에 직접 적지 않음)
