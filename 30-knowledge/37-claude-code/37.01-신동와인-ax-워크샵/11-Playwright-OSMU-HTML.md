F-1. 왜 이 세션이 필요한가
반복되는 비주얼 발행물이 어디에나 있다
매주 나가는 주간 리포트, 매일 만드는 제품 카드, 월별 SNS 캐러셀, 분기 보고서 표지, 수시로 발급되는 증명서·명함·포스터. 
이런 결과물을 Canva/파워포인트에서 매번 사람이 만들면 한 번에 5분이어도 한 달에 수 시간이 나간다.
이 모듈은 "한 번만 템플릿을 만들고, 그 다음부터는 내용만 바꿔서 기계가 찍어낸다"는 방식을 다룬다. 
이 방식의 핵심 엔진이 Playwright다.
여러분이 이미 쓰고 있는 도구다
web-crawler-ocr 스킬이 동작할 때 뒤에서 Playwright가 돌아가고 있다. 
즉 이 모듈은 새로운 도구를 배우는 게 아니라, 이미 워크스페이스에 있는 엔진을 정식으로 이해하고 반대 방향으로도 써보는 시간이다 (크롤링은 웹에서 가져오는 것, 이 모듈은 웹 기술로 결과물을 찍어내는 것).
F-2. 네 가지 개념
① Playwright
Playwright는 사람 없이 크롬을 조작하는 자동화 도구다. 
Microsoft에서 만들어 오픈소스로 공개했고, 웹 개발자들이 웹사이트 테스트·자동화·크롤링에 쓴다.
실제로 동작할 때 무슨 일이 벌어지는가
우리가 크롬을 손으로 쓸 때의 흐름:
크롬 아이콘 클릭 → 브라우저 실행
주소창에 URL 입력 → 엔터
페이지 로딩 기다림
스크롤, 클릭, 텍스트 선택
우클릭 → "다른 이름으로 저장" 또는 스크린샷
Playwright로 위 5단계를 코드로 쓰면 이렇게 된다:
const browser = await chromium.launch();   // 크롬 실행
const page = await browser.newPage();      // 새 탭 열기
await page.goto('file:///.../report.html');// 주소 입력
await page.waitForLoadState('networkidle');// 로딩 대기
await page.screenshot({ path: 'out.png' });// 찰칵 찍어 저장
await browser.close();                     // 크롬 닫기

​
즉 진짜 크롬이 실행되어 진짜 웹페이지를 렌더링한다. 
다만 모니터에는 창이 뜨지 않는다(=headless). 
내부 동작은 평소 쓰던 크롬과 완전히 동일하므로, 화면에 보이는 것과 Playwright가 찍는 결과물이 픽셀 단위로 같다.

② HTML
HTML은 웹페이지를 적는 방식이다. 태그로 구조를 표시한다.
<h1>큰 제목</h1>
<p>본문 한 줄</p>
<img src="사진.png">

​
HTML이 스킬 제작에 쓰이는 이유: 디자이너·개발자·AI가 모두 읽고 쓴다. 워드는 사람만, 피그마는 디자이너만 다루지만 HTML은 셋 다 다룬다. AI에게 "이 내용을 HTML로 정리해줘" 하면 즉시 만들어진다.
③ CSS 변수
CSS는 HTML에 입히는 옷이다. 
같은 사람(=HTML 구조)이어도 어떤 옷을 입느냐에 따라 전혀 다르게 보인다. 
색·폰트·여백·그림자까지 전부 CSS가 담당한다.
CSS 변수는 자주 쓰는 색·폰트를 한 줄에 이름 붙여두고 여러 곳에서 재사용하는 문법이다.
--bg-cream: #F3F2ED;    /* 크림 배경 */
--bg-forest: #1B3B36;   /* 딥그린 다크 배경 */
--accent: #D45D5D;      /* 포인트 빨강 */

세 줄만 자사 컬러로 바꾸면 이 템플릿을 쓰는 모든 결과물이 한 번에 교체된다. 
같은 템플릿을 여러 브랜드가 돌려 쓸 수 있게 설계하는 근거가 이 변수다. 
carousel-orchestrator 스킬이 이 원리로 브랜드 스왑을 구현한다.
④ OSMU (One Source Multi Use)
같은 소스 하나로 여러 포맷을 만드는 방식. 이 모듈에서는 기계가 자동으로 복제하는 OSMU를 다룬다.
같은 JSON 파일 한 개를:
dbt-slide가 읽으면 → 강의용 PDF
dbt-carousel이 읽으면 → 인스타 캐러셀 PNG
(확장) 뉴스레터 HTML, OG 썸네일, 인쇄용 포스터 등
핵심: 콘텐츠는 한 번 쓰고, 포맷은 기계가 복제한다.

F-5. 진행자 Q&A 대비 (예상 질문 5개)
Q1. "이거 디자이너가 할 일 아닌가요?"
첫 템플릿 디자인은 여전히 디자이너의 영역입니다. 다만 디자이너가 만든 템플릿을 매주 복제해서 찍어내는 일은 더 이상 디자이너에게 돌아가지 않아도 됩니다. 디자이너는 새 템플릿·새 시리즈 설계에 집중하고, 복제는 기계가 합니다. 디자이너 일이 줄어드는 게 아니라, 반복 노동이 줄어듭니다.
Q2. "코드를 못 쓰는데 가능한가요?"
이 세션에서 여러분이 타이핑하는 코드는 거의 없습니다. Claude Code가 템플릿과 렌더 스크립트를 대부분 씁니다. 여러분이 하는 일은 레퍼런스를 고르는 것, 구조를 설명하는 것, 결과물을 보고 피드백하는 것입니다. 이 세 가지는 비개발자의 강점이 가장 잘 드러나는 영역입니다.
Q3. "한 번 만든 스킬이 1년 뒤에도 돌아가나요?"
Playwright는 Microsoft가 만들고 유지보수하는 오픈소스이고, 웹 표준(HTML/CSS) 위에서 동작합니다. 즉 크롬이 살아있는 한 여러분의 스킬도 삽니다. 1년 뒤 패키지 업데이트 한 번(npx playwright install) 정도만 필요합니다.
Q4. "결과물 디자인 품질은 Canva보다 떨어지지 않나요?"
HTML/CSS로 만드는 디자인은 웹 브라우저가 그려내는 품질입니다. 여러분이 매일 보는 Apple 홈페이지·토스·배민 전체가 같은 기술로 그려집니다. 디자인 품질이 떨어지는 게 아니라 템플릿 작성자의 디자인 역량에 비례합니다. 좋은 레퍼런스에서 출발하면 Canva보다 더 일관된 결과물을 반복적으로 얻습니다.
Q5. "우리 회사 데이터를 외부로 안 보내도 되나요?"
Playwright는 여러분 컴퓨터에서만 돌아갑니다. 웹 서버도 없고, 외부로 데이터 보내지 않습니다. HTML 파일을 로컬에서 열어 로컬에서 찰칵 찍는 구조입니다. 보안 관점에서 오히려 안전한 선택입니다.
