F-1. 서브에이전트란
팀장 vs 전문 팀원
메인 에이전트(내가 대화하는 창)는 전체 방향을 잡는 팀장이다. 서브에이전트는 특정 영역만 전담하는 전문 팀원이다. 팀장이 직접 모든 일을 처리하는 게 아니라, 전문 팀원에게 위임하여 동시에 처리하게 하는 구조다.
핵심은 "모든 일을 다 하는 만능 에이전트"가 아니라, 한 가지를 잘하는 에이전트를 여럿 만들어 병렬로 돌리는 것이다.

F-2. 대화의 오염
하나의 주제에만 집중하라
한 창에서 리포트 작성을 하다가 갑자기 일정 등록을 시키면 맥락이 뒤섞인다. AI는 이전 대화 전체를 컨텍스트로 갖고 있기 때문에, 관련 없는 내용이 섞이면 이후 응답의 정확도가 떨어진다. 이것을 "대화의 오염"이라고 한다.
실전 원칙:
하나의 창 = 하나의 프로젝트 또는 주제
갑자기 생긴 다른 일은 새 창을 열어서 처리
서브에이전트는 아예 별도 컨텍스트로 실행되므로 메인 대화가 오염되지 않는다
예를 들어 작업 중에 전화가 와서 일정이 잡혔다면, 메인 창에 입력하지 말고 새 창을 열어서 캘린더에 저장하는 것이 좋다.
F-3. Skills vs Subagents
업무 매뉴얼 vs 전문 팀원
스킬은 SOP다. "이 순서대로 해"라고 정해놓는 것이다. 단계가 정해져 있고, 내용이 바뀌어도 절차는 같다.
서브에이전트는 전문가다. "이 분야 전문가야, 알아서 잘 해"라고 맡기는 것이다. 절차를 지정하지 않아도 해당 영역에서 스스로 판단하여 결과를 가져온다.

F-4. 병렬 처리가 핵심
경쟁사 분석: 순차 vs 병렬
서브에이전트를 쓰는 가장 큰 이유는 병렬 처리다.
[메인 에이전트만 사용 - 순차 처리]

A사 조사 → B사 조사 → C사 조사 → 비교분석 → 보고서

[서브에이전트 활용 - 병렬 처리]

A사 조사 ─┐
B사 조사 ─┼→ 비교분석 → 보고서
C사 조사 ─┘
​
A, B, C 조사가 서로 독립적이라면 순서대로 할 이유가 없다. 세 개를 동시에 시키고, 다 모이면 비교분석을 하면 된다.
매출 분석 사례: 12개월 병렬
1월부터 12월까지 월별 데이터를 분석하는 경우, 서브에이전트 12개가 동시에 실행된다. 메인 컨텍스트에는 영향을 주지 않고, 각자 분석을 완료한 후 결과만 돌려준다.
[12개월 병렬 분석]

1월 데이터 분석 ─┐
2월 데이터 분석 ─┤
3월 데이터 분석 ─┤
...              ─┼→ 연간 종합 분석 → 보고서
...              ─┤
11월 데이터 분석 ─┤
12월 데이터 분석 ─┘
​

F-6. 오케스트레이션: Decompose → Execute → Integrate
병렬 처리를 구조화하는 워크플로우다. 복잡한 미션을 잘게 나누고, 동시에 처리하고, 결과를 하나로 합친다.
1. /decompose - 일을 쪼갠다
가장 핵심 스킬. 큰 미션을 넣으면, Claude가 7단계 사고 과정을 거쳐서 작업을 분해한다.
입력:
/decompose 우리 업종 경쟁사 3곳 비교 분석 보고서 만들어줘.
각 경쟁사별 가격, 핵심 서비스, 타겟 고객, 온라인 채널 전략 조사.
비교표 + 우리가 참고할 포인트 정리.
​
Claude 내부에서 일어나는 7단계:
1단계: 최종 산출물 정의
  "이 미션이 끝나면 뭐가 나오지?"
  -> 경쟁사 비교 분석 보고서 (마크다운 문서)
  -> 저장 위치: 프로젝트 폴더

2단계: 필요한 입력 나열
  "이걸 만들려면 뭐가 필요하지?"
  -> 경쟁사 A 정보
  -> 경쟁사 B 정보
  -> 경쟁사 C 정보
  -> 3곳 비교 분석
  -> 최종 정리

3단계: 각 입력을 어떻게 얻을지 + 누가 할지 결정
  -> 경쟁사 조사 = 웹 검색이 필요 = research-worker
  -> 비교 분석 = 데이터 분석이 필요 = analysis-worker
  -> 보고서 = 글쓰기가 필요 = content-worker

4단계: 의존성 분석 - "이걸 먼저 안 하면 저걸 못 하나?"
  -> 경쟁사 A 조사: 독립 (바로 시작 가능)
  -> 경쟁사 B 조사: 독립 (바로 시작 가능)
  -> 경쟁사 C 조사: 독립 (바로 시작 가능)
  -> 비교 분석: A,B,C 조사가 끝나야 가능 (의존)
  -> 보고서: 비교 분석이 끝나야 가능 (의존)

5단계: 분류
  -> 병렬 가능: 경쟁사 A, B, C 조사 (동시에!)
  -> 순차 필요: 비교 분석 -> 보고서

6단계: 저장 경로 결정
  -> _parallel/ 폴더 안에 결과 파일 저장
  -> 파일명: 01-경쟁사A.md, 02-경쟁사B.md, ...

7단계: 매니페스트(작업 지시서) 생성
  -> _parallel/_manifest.md 파일 생성
​
7단계 결과로 만들어지는 매니페스트 파일:
_parallel/_manifest.md - 이게 전체 작업의 설계도다:

핵심: 나는 /decompose 한 줄만 쳤는데, Claude가 이 전체 설계를 자동으로 만든다.
2. /execute - 워커들을 보낸다
매니페스트가 만들어졌으면, 워커들을 투입한다.
/execute all
​
이 한 줄이면 된다. execute 스킬이 하는 일:
1. _parallel/_manifest.md 파일 읽기
2. pending 상태인 작업 찾기
3. 각 작업에 맞는 워커 호출
4. 독립 작업은 동시에, 의존 작업은 순서대로
5. 완료되면 매니페스트 상태를 completed로 업데이트
​
실행 과정:
[1] research-worker 실행 중... 경쟁사 A 조사  --|
[2] research-worker 실행 중... 경쟁사 B 조사  --|-- 3명이 동시에 작업
[3] research-worker 실행 중... 경쟁사 C 조사  --|

    ... 각자 웹 검색하고, 정보 모으고, 파일로 정리 ...

[1] 완료 -> _parallel/01-경쟁사A.md 저장
[2] 완료 -> _parallel/02-경쟁사B.md 저장
[3] 완료 -> _parallel/03-경쟁사C.md 저장

[4] analysis-worker 실행 중... 3곳 비교 분석
    (01, 02, 03 파일을 읽고 비교)
[4] 완료 -> _parallel/04-비교분석.md 저장

다음 단계: /integrate 실행하여 결과 통합
​
각 워커가 만드는 결과 파일 구조:
워커들은 정해진 형식으로 결과를 저장한다:
## 경쟁사 A 조사 결과

### 요약 (3줄 이내)
- 월 구독 모델, 가격대 15~30만원
- 타겟: 소규모 사업자
- 인스타그램 중심 마케팅

### 상세 내용
(... 조사한 전체 내용 ...)

### 메인 세션 전달 사항          <-- 이게 핵심!
- 통합 시 참고할 포인트: 가격 경쟁력 있음
- 다른 작업과의 연결점: B사와 같은 공급처 사용
- 미결정 사항: 최근 6개월 매출 데이터 확인 필요

​
"메인 세션 전달 사항"이 왜 중요한가: 나중에 /integrate할 때, 이 섹션만 쭉 읽으면 전체 그림이 보인다. 워커가 "이건 합칠 때 꼭 참고하세요"라고 남겨놓는 메모.
부분 실행도 가능:
/execute 1      <- 1번 작업만
/execute 1,2,3  <- 1,2,3번만
/execute all    <- 전부
​
내 메인 대화창은 그대로. 워커들이 별도 공간에서 일하고, 결과 파일만 _parallel/ 폴더에 떨어진다.
3. /integrate - 결과를 합친다
워커들이 다 끝나면, 결과를 하나로 합친다.
/integrate
​
이것도 한 줄. integrate 스킬이 하는 일:
1. _parallel/_manifest.md 읽기 - 원본 미션, 통합 지침 확인
2. 결과 파일 전부 수집 (01, 02, 03, 04...)
3. 각 파일의 "메인 세션 전달 사항" 종합
4. 연결점 파악 (A사 가격이 낮은 이유 = B사와 동일 공급처 등)
5. 통합 지침에 따라 최종 산출물 생성
6. 저장 후 _parallel/ 폴더 정리 여부 질문
   -> 삭제 / 아카이브 / 유지 중 선택
​
결과: 경쟁사 3곳 비교 분석 보고서가 하나의 파일로 완성.
4. 실행 중 폴더는 이렇게 생긴다

  +-- _parallel_archive_20260221/     <-- 아카이브 (선택)
        +-- (위 파일들 이동)

8. 어떻게 만드나?
서브에이전트 파일은 ~/.claude/agents/ 폴더에 있다.
~/.claude/agents/
  +-- research-worker.md      <- 리서치 전문
  +-- analysis-worker.md      <- 분석 전문
  +-- content-worker.md       <- 글쓰기 전문
  +-- design-worker.md        <- 디자인 전문
  +-- development-worker.md   <- 개발 전문

  +-- sns-essay-writer.md     <- SNS 글쓴이
  ...
​
새로 만들고 싶으면:
@subagent-guide.md
이 파일 참조해서 서브에이전트 만들자.

나는 경쟁사 리서치를 자주 하는데,
항상 가격/기능/타겟/차별점 4가지를 비교하고 싶어.
이 기준으로 리서치하는 전문 에이전트를 만들고 싶어.

Skills 만들 때와 같은 패턴. 공식 문서 @ 참조하고, 원하는 걸 말하면 된다.

결정 기준: 할 일이 매번 같고 판단이 불필요하면 스크립트. 매번 내용이 다르고 조사/분석/작성이 필요하면 서브에이전트. 스크립트는 컨텍스트를 소비하지 않으므로 단순 반복 작업에는 훨씬 효율적이다.
F-8. 서브에이전트 설정 위치와 구조
서브에이전트 파일은 .claude/agents/ 폴더에 저장한다. 스킬이 .claude/skills/에 있는 것처럼, 에이전트는 별도 폴더에서 관리된다.
에이전트 파일 구조
.claude/agents/
  research-worker.md      # 리서치 전문 에이전트
  analysis-worker.md      # 분석 전문 에이전트
  content-worker.md       # 콘텐츠 작성 에이전트
​
에이전트 파일은 마크다운 형식이다. 상단에 YAML frontmatter로 메타정보를 정의하고, 본문에 역할과 지시사항을 작성한다.
---
name: research-worker
description: 웹검색, 크롤링, 자료 수집 전문 에이전트
---

## 역할
웹에서 정보를 검색하고 수집하여 구조화된 결과를 반환한다.

## 지시사항
- 한국어와 영어 모두 검색한다
- 3개 이상 독립 소스에서 교차 검증한다
- 결과는 사실 기반으로 정리한다

​
에이전트 만들기 실습
스킬과 마찬가지로 Source of Truth를 참조하여 만든다.
@subagent-guide.md 참고해서 경쟁사 리서치 전문 서브에이전트를 만들어줘.
웹검색과 크롤링을 잘하고, 결과를 표로 정리하는 에이전트야.

서브에이전트
	
전문 팀원. 메인 창 토큰을 소비하지 않고 백그라운드에서 독립 실행


병렬 처리
	
독립적인 작업은 동시에 진행. 순서가 필요한 작업만 순차 처리


대화의 오염
	
한 창 = 한 주제. 다른 일이 생기면 새 창을 열어 처리


Skills vs Subagents
	
절차가 있는 일 → 스킬 / 매번 다른 내용 → 서브에이전트


Scripts vs Subagents
	
같은 작업 전체 반복 → 스크립트 / 내용이 다른 조사 및 분석 → 서브에이전트


Decompose
	
미션 분해. 의존성 분석 후 독립 작업은 병렬, 의존 작업은 순차 배치


Execute
	
작업지시서 기반으로 워커 에이전트 병렬 투입


Integrate
	
모든 결과를 하나의 최종 산출물로 통합
