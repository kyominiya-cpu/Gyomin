Part 1: Claude Code 잘 쓰는 법 
Tip 1. 한번에 다 하려고 하지 마라
가장 중요한 원칙이다. Claude Code에게 "매출 데이터 분석해서 대시보드 만들어줘"라고 한 번에 시키면 높은 확률로 원하는 결과가 안 나온다.
안 되는 방법
"엑셀 파일 분석해서 매출 트렌드 대시보드 만들어줘"
→ 엑셀 구조 파악 실패, 잘못된 컬럼 참조, 어설픈 차트
​
왜 안 될까? 여러분이 다루는 엑셀 데이터를 생각해보자. 
병합 셀, 소계행, 날짜 형식 뒤죽박죽, 시트가 여러 개... 
이미 정렬도 안 되어 있고 뽑아오기도 힘든 데이터를 "한번에 해줘"한다고 되지 않는다.


핵심: 데이터가 복잡하다면, AI가 오차 없이 읽기 좋게 만드는 게 먼저다.
이걸 깨닫고 단계를 쪼개봤다:
Step 1: 엑셀 → CSV 변환 (AI가 읽을 수 있는 형태로)
Step 2: CSV 정리 (소계행 제거, 날짜 통일, 빈 행 제거)
Step 3: 그제야 "이 데이터로 분석해줘"
​
Step 1~2를 반복하다 보니, 아예 스킬로 만든 것이 /excel-to-csv와 /csv-clean이다. 
오늘 설치할 Plugin(dbt-ax-toolkit)에 들어있다.

Tip 2. Progress 파일을 만들어라
Claude Code는 대화가 끝나면 기억을 잃는다. 
새 세션을 시작하면 어제 뭘 했는지 모른다.
해결책: 프로젝트마다 progress 파일을 만들어서 업데이트한다.
내-프로젝트/
├── CLAUDE.md          <- 프로젝트 규칙 (항상 로드)
├── progress.md        <- 진행 상황 기록 (필요 시 참조)
└── (작업 파일들)
​
progress.md에 들어가는 것:
현재 상태 (어디까지 했는지)
최근 변경 사항 (날짜별)
다음에 할 것
결정 사항과 이유
사용 패턴:
"progress.md 읽고 이어서 작업해줘"
→ Claude가 맥락을 파악하고 이어서 진행

(작업 완료 후)
"오늘 한 작업을 progress.md에 업데이트해줘"
→ 다음 세션을 위한 기록 남기기
​
이렇게 하면 Claude Code의 "기억상실"을 파일 시스템으로 보완할 수 있다. 대화는 사라져도 파일은 남는다.
Tip 3. /clear를 두려워하지 마라
대화가 길어질수록 Claude의 성능이 떨어진다. 컨텍스트 윈도우에 이전 실패 시도, 관련 없는 탐색 결과가 쌓이면서 혼란이 생긴다.
규칙: 같은 문제를 3번 수정해도 안 되면, /clear 하고 처음부터 다시 시작한다.

Anthropic이 공식적으로 명명한 실패 패턴: "Kitchen sink session" -- 한 세션에서 무관한 여러 작업을 섞으면 모든 작업의 품질이 떨어진다.
/clear는 리셋이 아니라 새 출발이다. CLAUDE.md와 파일은 그대로 남아있으니 맥락은 유지된다.

Tip 6. Plan Mode를 습관화하라
복잡한 작업을 시작할 때, 바로 "해줘"가 아니라 Shift+Tab으로 Plan Mode를 켠다.
[Plan Mode ON]
"매출 데이터로 월별 트렌드 분석을 하고 싶어"
→ Claude가 실행 없이 계획만 세움
→ 계획 확인 후 승인
→ 그제야 실행

[Plan Mode OFF - 일반 모드]
"매출 데이터로 월별 트렌드 분석 해줘"
→ 바로 실행 시작
→ 방향이 틀리면 되돌리기 어려움
​

Part 2: 개념 -- Skill vs Plugin
현재 상태 (개인 Skill)
내 컴퓨터
└── .claude/skills/voc-analysis/SKILL.md    -> /voc-analysis (나만 씀)
​
다른 사람이 쓰려면? 파일을 복사해서 보내야 함
업데이트하면? 다시 복사해서 보내야 함
3명이 각자 만든 스킬이 이름이 겹치면? 충돌
Plugin으로 바뀌면
dbt-ax Plugin
├── skills/voc-analysis/SKILL.md            -> /dbt-ax:voc-analysis
└── commands/report.md                      -> /dbt-ax:report
​
다른 사람이 쓰려면? /plugin install dbt-ax
업데이트하면? /plugin update dbt-ax
이름 충돌? 네임스페이스로 자동 분리

Plugin 이름 규칙 -- 겹치면 안 된다
같은 이름의 Plugin은 한 환경에 동시 설치할 수 없다. 15명이 각자 Plugin을 만들면 이름이 모두 달라야 한다.
이름 규칙: 영문 kebab-case만 가능 (한글 불가)
방식은 자유. 업무 기반이든 이름 기반이든 겹치지만 않으면 된다.

Step 3: 마켓플레이스 등록 (참여자 각자, 터미널에서 1회)

충돌 방지 규칙
자기 폴더만 건드린다 -- 다른 사람 Plugin 폴더는 수정하지 않음
Claude Code가 push 전에 자동으로 pull을 먼저 하므로 충돌이 거의 없다
만약 충돌이 나면 Claude Code에게 "충돌 해결해줘"라고 시키면 된다
관리 명령어 요약
/plugin list                    # 설치된 Plugin 목록
/plugin info dbt-ax           # 상세 정보
/plugin disable dbt-ax        # 임시 비활성화 (제거 안 함)
/plugin enable dbt-ax         # 다시 활성화
/plugin uninstall dbt-ax      # 제거
/reload-plugins                 # 세션 재시작 없이 변경 적용
