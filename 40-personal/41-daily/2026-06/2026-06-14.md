## 완료한 일

> **통관서류 대시보드(`10-projects/11-통관서류-대시보드/dashboard-app/`)를 0부터 실동작 앱으로 구현.** Next.js + TypeScript, dev 서버 :3000.

**기반 구축**
- Claude Design 프로토타입을 Next.js로 픽셀-퍼펙트 포팅 (대시보드 / 상세 / SKU 3화면, 버건디 톤·IBM Plex)
- 조건 분기 엔진(`requiredDocs`): 거래유형 × FTA × 카테고리 → 필수 서류 자동 산출
- 실제 폴더 저장(Node fs, §4 규칙대로 이름변경) + 현황 Excel 다운로드(SheetJS)

**기능 단계별 추가**
- **통합 마스터 엑셀 연동**: 마스터 읽어 화면 구성, 없으면 샘플 폴백 + 마스터 템플릿 다운로드
- **신규 와이너리 등록 + 서류 자동 분류**: 폼 + 파일 일괄 드롭 → 파일명·PDF 텍스트로 종류 자동 판별
- **발주 가능 스테이지**: 성분표 + 제조업소코드(K-MFDS)만 확인되면 우선 발주 가능 (미착수→진행중→발주가능→통관가능)
- **직접 검토 게이트**: 각 서류 §3 조건 체크리스트 확인 → 검토완료/이상. 검토를 거쳐야 다음 단계로
- **상세 업로드 간소화**: 드롭다운 제거 → 박스에 넣으면 자동 분류·저장 후 검토 대기
- **와이너리 이름 수정 / 삭제** (사이드카 처리)
- **일괄 자동 검토 버튼**: 수령 서류를 조건으로 자동 판정 (EEC·0%·SO2·주소 불일치 감지) → 검토완료/이상

**중요: 원본 보호 구조**
- 교민의 실제 마스터 엑셀(`OneDrive\바탕 화면\통관서류_MASTER.xlsx`, 공급사 5곳·SKU 48개) 구조를 그대로 읽도록 어댑터 작성
- 모든 쓰기(검토·업로드·이름수정·삭제·등록)는 **앱 내부 사이드카(`.data/sidecar.json`)** 에만 → 원본 .xlsx 미수정

## 배운 것 / 인사이트

- **AI 도구 핸드오프 흐름**: PRD(dashboard-prd) → Claude Design(시각) → Claude Code(실구현) 한 줄로 이어짐. 디자인 프로토타입이 엔진·샘플데이터까지 담고 있어 포팅이 빨랐음.
- **실무 데이터 ≠ 표준 양식**: 내 앱 스키마보다 교민의 실제 엑셀 구조(원본 PRD 컬럼)에 앱을 맞추는 게 맞다. "원본 보호 + 사이드카"가 비개발자 단일 파일 워크플로우에 안전.
- **자동화의 정직한 한계**: 마스터 칸이 "있음" 같은 상태 마커면 내용 검증 불가 → 실제 파일을 업로드해야 PDF 내용까지 검증 가능.
- (반성) 쓰기 API를 실서버로 테스트해 원본 마스터를 한 번 건드림 → 테스트는 임시 경로(DEST/MASTER)로 격리해야 함. OneDrive 버전 기록으로 복원 가능.
