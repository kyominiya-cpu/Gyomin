# 업무 재진입 시스템 (Task Re-entry System)

> 여러 속도의 업무를 동시에 굴릴 때, **미뤄둔 일을 다시 켜는 비용**을 낮추기 위한 운영 방식.
> 2026-06-13 thinking-partner 세션에서 도출.

## 진단 — 진짜 병목은 "재진입(re-entry)"

이미 잘 되고 있는 것:
- **캡처** ✅ 모든 업무를 엑셀 시트에 기록 → 잘 안 놓침
- **상태 기록** ✅ 시간이 허락하면 흐름(history)도 다 적어둠

막히는 지점 = 며칠 텀이 뜬 일을 **다시 꺼낼 때**, 두 겹으로:
- **A. 떠오르질 않음 (surfacing)** — 엑셀이 가만히 있어서 "챙길 때가 됐다"고 안 알려줌. 다른 일 하다 보면 그 일의 존재 자체를 잊음.
- **B. 다시 읽기가 무거움 (re-reading)** — 찾아도 흐름 전체를 처음부터 다시 읽어야 함.

**핵심 통찰**: A와 B는 뿌리가 같다. 엑셀이 *캡처에 최적화*돼 있어 *꺼내기엔 안 맞음*.
- 시간 개념이 없으니 → 스스로 떠오르지 못함 (A)
- 흐름이 시간순으로 길게 쌓이니 → 다시 읽기가 무거움 (B)
- 즉, 잘하고 있는 "흐름 다 적기"가 오히려 B의 비용을 키우는 구조.

> 관련 철학: *"지식은 한 번 컴파일해두고 최신으로 유지하는 것이지, 매 질문마다 다시 유도하는 게 아니다."* (워크스페이스 SCHEMA 인용)
> → 미뤄둔 일마다 매번 다시 유도(re-derive)하지 말고, 꺼내기 쉬운 형태로 한 번 컴파일해 둔다.

## 해법 — 컬럼 2개 + 아침 1분 루틴

시트 구조는 그대로 두고, 그 위에 *꺼내기용 레이어*만 얇게 얹는다.

### ① 상태 한 줄 (헤드라인) — B를 풂
기존 흐름 칸은 그대로 두되, **맨 앞에 "지금 상태"만 요약한 한 줄**을 별도 칸으로. 이 칸은 **덮어쓴다** (일에 변화가 생길 때마다 이 한 줄만 갱신).

형식 고정:
```
⏳ [기다리는 것]   ▶ [다음 내 액션]
```
예시:
- `⏳ A공급사 COA 회신 대기   ▶ 오면 통관서류철 편철 후 관세사 송부`
- `▶ B와인 라벨 심의서류 작성 (대기 없음, 바로 진행)`

→ 며칠 뒤 열면 **이 한 줄만** 읽으면 됨. 전체 흐름은 아래 칸에 살아있으니 깊게 볼 때만 내려가서 봄.

### ② 다음 확인일 — A를 풂
일을 미룰 때(특히 남에게 공을 넘길 때) **"언제 다시 볼지" 날짜를 박는다.**
- 공급사 메일 보냄 → 회신 보통 3일 → 확인일 = +3일
- 그날이 오면 시트가 그 일을 수면 위로 올림.

→ 엑셀이 *가만히 있는* 문제를 깨는 건 **시간 트리거** 하나면 된다.

### ③ 아침 1분 루틴 — 둘을 작동시킴
출근하면 시트를 **"다음 확인일" 기준 정렬/필터** → `확인일 ≤ 오늘`인 행만 본다.
- 그 행들의 **헤드라인 한 줄**만 읽으면 → 오늘 챙길 것 + 각각 어디까지 갔는지 한눈에.
- 떠올릴 필요 없이 시트가 "오늘은 이것들"이라고 밀어줌 → **우선순위까지 자동 정리.**

## 한 줄 요약

> 적을 때 **한 줄 더(헤드라인)** + 미룰 때 **날짜 하나(확인일)** + 아침 **1분 필터.**
> → A(떠오름)와 B(다시 읽기)가 같이 풀린다.
